# Useless 4370 Silencer

## 면책 사항

이 소프트웨어를 사용함으로서 발생되는 모든 피해에 대해 책임지지 않습니다. 애초에 풍자 소프트웨어인걸요.

어떻게 쓰는 지 모르겠다구요? 괜찮습니다! 이거 쓰라고 만든 거 아니에요.

## 들어가며

ETSI TS 123.041 에 따르면 MessageIdentifier 4370 은 다음과 같은 용도로 사용됩니다:

* CMAS Presidential Level Alerts
* EU-Alert Level 1
* KPAS class 0 (aka. 위급재난문자)

아무래도 모두들 정말로 위험할 때 써야 할 것 같은 최고 레벨 경보인데, 이 중 역대 KPAS class 0 으로 전송된 브로드캐스트 내용을
살펴보자면

* [서울은 위험합니다 여러분 (실제로 위급하지 않았음, feat. 오세이돈)](https://www.khan.co.kr/article/202305310835001)
* [수능은 위험합니다 여러분 (실제로 위급하지 않았음, feat. 이재명)](https://www.yna.co.kr/view/AKR20261118032651530)

아무래도 패턴상 MCC 450 에서 날아오는 4370 메시지는 위급하지 않을 때 양치기 소년 메타로 보내는 게 틀림없습니다.

이 중에서 모 웹툰을 감명깊게 본 것 같은 두번째 항목에 대해 살펴보자면, 뭐 수능 때 재난문자 보내서 휴대폰을 울리게 해서 휴대폰 반입한
놈을 잡겠다 뭐 이런 발상 같은데, 이건 휴대폰이 ETSI / TTA 스펙을 준수할 때의 이야기이고

노프신 분들은 모르는 것 같지만, 놀랍게도, 스펙 준수를 하지 않는 UE 구현체가 존재하기 불가능한 건 아니죠.
모뎀 써서 대충 얼기설기 만든 휴대폰이 아닌 물건들은 어차피 이런 거 안 써도 재난문자 핸들링 기능이 없네요. 참 신기하죠?
그리고 휴대폰도 소프트웨어를 수정하면 와! 4370 메시지가 조용히 씹히게 만들 수 있네요!

이거 만드는 게 기술적으로 어렵지 않냐고요? 네 이건 다음 문단에서 살펴봅시다

## 어떻게 만들어졌나

1. 안드로이드 스튜디오를 다운로드 받습니다
2. 빈 안드로이드 앱 프로젝트를 생성합니다
3. AI 에이전트를 대충 셋업합니다
4. `YukiHookAPI 를 사용해서 MCC = 450, MessageIdentifier = 4370 인 Cell broadcast 를 무시하게 하는 모듈을 만들고 싶어.`
5. 기다립니다
6. 완료!
7. 이게 그리 어려워 보입니까?

## 동작 요약

참고: 매우 당연하겠지만, 이 모듈은 AOSP 기준으로 작성되고 테스트 되었으며, Xposed 호환 훅 프레임워크를 필요로 합니다.

참고2: 심 카드가 없을 때에는 `com.android.cellbroadcastservice` 에 Location 이 전달되지 않아, PLMN 필터가 쓰루됩니다.

쓸모없는 메시지 타율 100% 를 자랑하는 MCC = 450, MessageIdentifier = 4370 을 가지고 수신되는 셀 브로드캐스트를 중복으로
마킹합니다.

셀 브로드캐스트는 그 특성상, 중복 수신이 필연적이기 때문에 (말 그대로 LTE 셀 브로드캐스트니까요), 중복 수신 시 메시지를 무시하는
메커니즘을 가지고 있습니다.

이 LSPosed 모듈은 `com.android.cellbroadcastservice.CellBroadcastHandler::isDuplicate()` 에 훅을 걸어
MCC = 450, MessageIdentifier = 4370 일 경우, 함수 리턴을 중복 여부와 상관 없이 true 로 리턴합니다.

## 결론

노프신 분들에게: 셀 브로드캐스트 4370 을 원래 목적 외의 용도로 오용하지 마세요. 뭐 늑대가 나타나서 모든 양을 먹어치우는 엔딩을
바란다면야 계속 하던대로 오용하시구요.
